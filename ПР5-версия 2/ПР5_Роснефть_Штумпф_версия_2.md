## 2.1. Почему именно эти пять улучшений

Эти улучшения выбраны не потому, что они самые простые, а потому что они закрывают главные разрывы ПР1 5.0, лебедей №3 / №4 и сценарных долгов.

| Разрыв из ПР1 / лебедей / сценариев | Какое улучшение отвечает |
|---|---|
| Красная зона: отсутствие управляемого быстрого B2B-канала | U1 |
| Лебедь №3: быстрый онбординг без контроля ухудшает DSO на +14 дней и нагружает исключения до 50% | U1 + U2 |
| Жёлтая / частично красная зона: секвестр 25% без учёта protected-сервисов и поддержки канала | U3 |
| Лебедь №4: protected-сервисы требуют 10% экономии, но CISO не может снизить мониторинг КИИ | U5 |
| Лебедь №4: parallel run 30–90 дней блокирует read-only телеметрию в ЕЦПК | U4 |
| Сценарий 33: нет метрик скорости добычи и переработки, бюджет унификации 2–4 млрд ₽ не сверен с секвестром | U3 + U4 |
| Сценарий 51: нет freeze registry, BIS, fallback readiness, декомпозиции упущенной маржи | U1 + U3 |
| Сценарий 95: buy / build / partner не управляется через DD, retention, integration cost, сроки | U1 + U3 |
| «Остановка без правил»: нет RCA, change control, parallel run, rollback | U4 |
| «Потолок доверия»: критичные решения не подписаны, нет owner, age of decisions не измерен | U5 |

Г4 «покупка технологической команды» не включена как базовое улучшение, потому что белый лебедь №7 не назначен. Она остаётся опцией / fallback в процессе ПР3 и может рассматриваться только при прохождении due diligence.

Г5 «ИИ-оптимизация переработки» не включена как самостоятельное денежное улучшение, потому что остаётся в резерве до change control, RCA, data contract, speed metrics и read-only телеметрии. U4 частично готовит почву для будущего выхода Г5, но не обещает эффект ИИ сейчас.

# 3. Совокупный эффект: не простая сумма

Требование курса: эффект набора изменений не равен сумме эффектов отдельных изменений. Здесь это показано явно и с разделением на execution bottleneck и scenario constraints.

## 3.1. Простая сумма индивидуальных эффектов по выручка-эквиваленту

| Улучшение | Эффект, млрд ₽ |
|---|---:|
| U1 | +10,50 |
| U2 | +0,15 |
| U3 | +18,80 |
| U4 | +0,40 |
| U5 | +0,05 |
| **Простая сумма** | **29,90** |

Как доля выручки 2025 г.:

```text
29,90 / 8 236 = 0,363%
```

Но эта цифра **не является итоговым совокупным эффектом**, потому что содержит пересечения, взаимное усиление, общее узкое место и сценарные ограничения.

| Пересечение | Почему возникает | Корректировка, млрд ₽ |
|---|---|---:|
| U1 и U2 | U2 — кредитные guardrails — уже является условием масштабируемости U1. В модели U1 выручка 10,5 млрд ₽ получена не при «полном отсутствии риска», а при контролируемом DSO. Если считать U1 и U2 как полностью независимые, часть эффекта DSO / bad debt учитывается дважды | **−0,20** |
| U3 и U5 | U3 уже предполагает protected-фильтр и оргрезерв. U5 добавляет формальный risk acceptance и избежание инцидентов, но часть этого риска уже заложена в консервативный waterfall U3 | **−0,10** |
| U4 и U1 / U3 | U4 ускоряет решения и разблокирует read-only телеметрию. Часть управленческого эффекта уже косвенно учтена в ramp-up U1 и оргрезерве U3 | **−0,15** |
| **Итого пересечения** |  | **−0,45** |

## 3.3. Взаимное усиление: где одно улучшение делает возможным другое

| Синергия | Механика | Корректировка, млрд ₽ |
|---|---|---:|
| U3 → U1 | Секвестр с явной строкой поддержки канала 0,5–1,0 млрд ₽/год делает цифровой канал финансируемым сервисом, а не «бесплатным» проектом. Без этого U1 рискует деградировать после MVP | **+0,20** |
| U4 → U1 / U3 | Приоритетный комитет, risk-based parallel run, speed metrics и production change standard снижают риск блокировки решений «канал vs ЕЦПК», read-only телеметрии и производственных изменений. Это ускоряет ramp-up U1 и исполнение U3 | **+0,10** |
| U2 → U1 | Кредитные guardrails делают U1 масштабируемым: без них быстрый канал превращается в канал просрочки и стоп-триггеров | **+0,05** |
| **Итого усиление** |  | **+0,35** |

## 3.4. Общее узкое место: почему все пять не случатся одновременно на полную мощность

Главное ограничение — не идея, а пропускная способность людей и систем.

| Узкое место | Какие улучшения тормозит | Оценка потери одновременного эффекта, млрд ₽ |
|---|---|---:|
| Кредитный блок, юристы, exception queue | U1, U2 | **−0,70** |
| «Сибинтек» / ЕЦПК / product owner канала / интеграции SAP / 1С | U1, U3, U4 | **−0.70** |
| CDO / CFO / приоритетный комитет / governance | U3, U4, U5 | **−0,40** |
| **Итого execution bottleneck** |  | **−1,80** |

Это не пессимизм ради пессимизма. Лебедь №3 прямо сказал: людей у ИТ после пропорционального сокращения не прибавилось, юристы и кредитный комитет перегружены, доля сложных клиентов может достигать 50%. Лебедь №4 добавил: решение по приоритету ЕЦПК никто не готов подписать, protected-сервисы конфликтуют с секвестром, parallel run блокирует данные.

## 3.5. Сценарные ограничения: отдельный слой, а не прячущийся в общем узком месте

В ПР5 1.0 часть сценарных рисков была спрятана в общем узком месте. В ПР5 2.0 они выделены отдельно.

| Сценарный фактор | Что может пойти не так | Консервативный reserve, млрд ₽ |
|---|---|---:|
| С33: бюджет унификации 2–4 млрд ₽ не полностью сверен с protected costs / waterfall | Риск скрытого превышения расходов; чистая экономия переоценена | **−0,15** |
| С51: freeze registry неполный, BIS формальный, возможна тихая разморозка | Экономия секвестра не подтверждена | **−0,10** |
| «Остановка без правил»: RCA open, production changes без parallel run / rollback | Риск инцидента, остановки, переделок | **−0,10** |
| «Потолок доверия»: критичные решения без owner, age >10 дней | Исполнимость программы снижается, даже если модель красивая | **−0,05** |
| **Итого scenario constraints** |  | **−0,40** |

Эти величины не являются новыми «штрафами» сверх ПР4. Это явное разделение того, что раньше частично сидело в общем узком месте. Итог сохраняется, но структура становится проверяемой.

## 3.7. Чистый EBITDA-эффект после trade-off

Для EBITDA нельзя складывать выручку U1 и экономию U3 как одно и то же. Для U1 берётся инкрементальная маржа, а не вся выручка.

| Компонент | млрд ₽ |
|---|---:|
| U1: инкрементальная маржа от пилотной когорты | +0,90 |
| U2: избежанный кредитный / операционный убыток | +0,15 |
| U3: чистая экономия ИТ-бюджета | +18,80 |
| U4: избежанные задержки / rework data-layer и production change standard | +0,40 |
| U5: net risk-control effect | +0,05 |
| Простая сумма EBITDA-эффектов | +20,30 |
| Пересечения в EBITDA-логике | −0,35 |
| Взаимное усиление | +0,25 |
| Execution bottleneck | −1,35 |
| Scenario constraints | −0,25 |
| **Чистый совокупный EBITDA-эффект** | **≈18,60** |

Как доля выручки:

```text
18,60 / 8 236 = 0,226%
```

> **Чистый EBITDA-эффект: ≈18,6 млрд ₽/год, или ≈0,23% выручки.**

Это согласуется с ПР4 2.0. Разница с более ранними оценками в том, что сценарные ограничения теперь показаны отдельно, а не растворены в общей поправке.

## 3.8. Что ухудшается: устойчивые trade-off, а не разовые затраты

| Мера | Что улучшаем | Что ухудшаем | Цена / риск |
|---|---|---|---|
| Экспресс-онбординг только для низкорисковых | Скорость захвата, конверсия, окно 6 месяцев | Часть сложных клиентов не проходит за 5 дней | Потеря части сделок или необходимость ручной очереди |
| Ужесточение скоринга и guardrails | Снижение DSO и bad debt | Более длинный онбординг для пограничных клиентов | Упущенные клиенты, нагрузка на кредитный блок |
| Exception queue | Управление сложными рисками | Растёт backlog при доле исключений до 50% | 0,15–0,45 млрд ₽/год устойчивого операционного ухудшения, перегрузка юристов / кредитного комитета |
| Отказ базово резать SOC / КИИ / АСУ ТП / кассы АЗС | Безопасность, соответствие, непрерывность | Меньше экономии по protected-статьям | Потеря потенциальной protected-экономии ≈0,45 млрд ₽; компенсируется избежанием инцидента ≈0,50 млрд ₽ |

| Freeze registry и BIS | Качественная заморозка | Административная нагрузка, slower unfreeze | PMO / аудит / комитет |

| Risk-based parallel run | Ускорение некритичных read-only миграций | Нужен зрелый architectural governance | Стоимость аудита интерфейсов и data contract |
| Production change standard / RCA closure | Снижение риска остановки | Замедление производственных изменений | 0,2–0,5 млрд ₽ на крупный перенос; governance-нагрузка |
| Fallback readiness | Независимость от M&A | Vendor lock, ИБ, качество | 0,8–1,5 млрд ₽ как опция, не базовый эффект |
| Governance trust / age of decisions | Подписанные приоритеты | Дополнительная управленческая нагрузка | Приоритетный комитет, decision log, эскалация |

# 5. План пилота на реальных пользователях и управленческих проверках

Пилот — главный раздел. Модель показывает, как система может отреагировать, но подтверждает улучшение только пилот на реальных пользователях с контрольной группой.

Основной пользовательский пилот делается для **U1 + U2**, потому что именно там есть прямой клиентский риск, кредитный риск и проверка гипотезы цифрового канала.

Для сценарных долгов С33 / С51 / С95 / «Остановка без правил» / «Потолок доверия» добавляются управленческие пилоты / аудиты. Они не заменяют пользовательский пилот, но без них программа может быть заблокирована старыми долгами.

---

## 5.1. Пилот A. Основной пользовательский пилот: U1 + U2

| Параметр | Значение |
|---|---|
| Пилотируемые улучшения | U1 — двухконтурный экспресс-онбординг низкорисковых новых B2B-клиентов; U2 — кредитные guardrails и когортный мониторинг DSO |
| Связь с гипотезой | Г1 ПР2 5.0 |
| Связь с процессом | ПР3 3.1, Процесс 1 |
| Связь с лебедем / сценарием | Лебедь №3: риск ухудшения DSO на +14 дней и роста исключений до 50%; С51: fallback и декомпозиция маржи; С95: build / buy / partner gate |
| Цель пилота | Проверить, даёт ли экспресс-контур экономически значимый приток новых B2B-клиентов без ухудшения DSO, маржи и кредитного качества |

---

### 5.1.1. Сегмент: на ком проверяем

Сегмент должен приносить деньги, а не быть самым удобным.

| Критерий сегмента | Значение |
|---|---|
| Тип клиентов | Новые мелкие и средние B2B-оптовики, не действующие крупные контрактные клиенты |
| Продукт | Стандартные нефтепродукты / типовые продукты переработки без экспорта и спецлогистики |
| География | 2–3 пилотных региона с подтверждённым высвобождаемым спросом и логистическим покрытием |
| Годовой потенциал клиента | 150–250 млн ₽, база 200 млн ₽ |
| Кредитный профиль | Начальный скоринг выше порога экспресс-контура; без признаков мошенничества; согласие на предоплату / частичную предоплату или обеспечение |
| Исключения из пилота | Экспорт, спецконтракты, крупный лимит, слабая отчётность, нестандартная логистика, признаки fraud, клиенты с историей просрочки в группе |

Почему этот сегмент:

- он достаточно массовый, чтобы проверить канал;
- он не самый сложный, но и не «удобный внутренний» клиент;
- он находится в окне захвата клиентов уходящих конкурентов;
- по нему можно измерить DSO, маржу и повторные отгрузки.

---

### 5.1.2. Контрольная группа

Контрольная группа обязательна. Без неё нельзя отличить эффект канала от рыночного спроса, сезонности, работы менеджеров или изменения цен.

| Параметр контрольной группы | Значение |
|---|---|
| Кто остаётся без изменения | Сопоставимые новые B2B-заявки в контрольных регионах / от контрольных менеджеров, обрабатываемые по существующему процессу |
| Метод формирования | Cluster randomization по регионам / торговым территориям / группам менеджеров, чтобы избежать contamination между пилотным цифровым каналом и ручным процессом |
| Сопоставимость | Matching по продукту, региону, размеру клиента, начальному кредитному скору, типу канала привлечения, сезону |
| Предпериод | 3 месяца до старта пилота для baseline по срокам, конверсии, DSO, марже |
| Shadow-скоринг | Для контрольной группы применяется та же модель скоринга в режиме «теневой классификации», чтобы понять, сколько клиентов были бы eligible для экспресс-контура, но они не получают новый цифровой опыт |

Важно: контрольная группа не должна получать доступ к новому личному кабинету, автоматическому экспресс-лимиту или ускоренному шаблонному договору. Иначе эффект будет размыт.

---

### 5.1.3. Главная метрика решения

Выбирается одна главная метрика. Она задаётся до запуска и не меняется постфактум.

| Параметр | Значение |
|---|---|
| Главная метрика | Инкрементальная маржа пилотной когорты на 100 первичных новых B2B-заявок, annualized |
| Формула | `incremental_margin_pilot_cohort / primary_new_b2b_applications × 100`, annualized по первому полному циклу |
| Порог успеха | **≥100 млн ₽ инкрементальной маржи на 100 заявок в annualized выражении** |
| Базовое модельное ожидание | ≈118 млн ₽ на 100 заявок при выручке 10,5 млрд ₽ и марже ~9% |
| Почему порог 100, а не 118 | Порог задаётся консервативно: если пилот даёт меньше 100 млн ₽ на 100 заявок, масштабирование U1 не оправдано, даже если медианный срок ≤5 дней |

Альтернативно можно было бы взять медианный срок онбординга, но это процессная метрика. Главная метрика должна быть бизнес-решением: приносит ли канал маржу, а не просто ускоряет бумаги.

---

### 5.1.4. Длительность пилота

| Параметр | Значение |
|---|---|
| Основная длительность | 6 месяцев |
| Промежуточный контроль | 90 дней |
| Расширенная проверка | 12 месяцев для повторных отгрузок и stable DSO |
| Почему 6 месяцев | Окно захвата клиентов уходящих конкурентов по лебедю №3 — около 6 месяцев. B2B-цикл «заявка → договор → первая отгрузка → оплата» требует минимум одного квартала, а для оценки повторных отгрузок — двух кварталов |
| Дата старта | 01.12.2026, после утверждения приоритетным комитетом |
| Дата промежуточного решения | 01.03.2027 |
| Дата основного решения | 01.06.2027 |

### 5.1.5. Защитные метрики

Защитные метрики показывают, что не должно ухудшиться, пока улучшается главная метрика.

| Защитная метрика | Порог | Почему важна |
|---|---:|---|
| DSO новой когорты | Ухудшение не более чем на +10 дней относительно baseline | Лебедь №3: риск +14 дней; без guardrails быстрый канал ухудшает кэш-флоу |
| Доля исключений в общем потоке | Не более 50% после 90 дней; целевое ≤35% | Если исключений слишком много, автоматизация не даёт эффекта |
| Инкрементальная маржа | Не ниже 8% | Низкомаржинальные новые клиенты могут съесть эффект скорости |
| Fraud / сомнительные заявки | Не выше установленного кредитного порога; любой material fraud — ручной разбор | Защита от прохода подставных / слабых контрагентов |
| Bad debt по когорте | Не выше baseline для сопоставимых новых клиентов | Проверка качества кредитного решения |
| Доступность цифрового канала | Uptime ≥99% для критичных шагов онбординга | Канал не должен деградировать из-за секвестра |
| Критичные инциденты ИБ / КИИ | 0 инцидентов, связанных с пилотным каналом или protected-сокращениями | Лебедь №4: нельзя экономить ценой КИИ |
| Нагрузка юристов / кредитного комитета | Backlog не растёт более 2 недель подряд | Иначе исключительный контур становится новым узким местом |
| Fallback readiness | ≥80% перед запуском, если buy не подтверждён | С51 / С95: канал не должен зависеть от непроверенной M&A |
| Age of unresolved critical decisions | ≤10 рабочих дней по вопросам канала / ЕЦПК / protected / freeze | «Потолок доверия»: зависшее решение блокирует пилот |

### 5.1.6. Критерии остановки пилота A

Критерии остановки фиксируются до запуска. Они означают: не «дожимать», а останавливать и пересобирать.

| № | Наблюдение | Порог | Действие |
|---|---|---:|---|
| A-S1 | DSO новой когорты ухудшается | >+10 дней 2 месяца подряд | Приостановить экспресс-режим для сомнительного сегмента; перевести в предоплату / обеспечение |
| A-S2 | Доля исключений | >50% после 90 дней | Пересмотреть критерии экспресс-контура; остановить масштабирование |
| A-S3 | Главная метрика | Annualized margin <60 млн ₽ на 100 заявок к дню 120 и тренд не улучшается | Пилот останавливается как не подтвердивший U1 |
| A-S4 | Инкрементальная маржа | <8% | Не расширять скидочный / логистический микс; пересобрать продуктовые условия |
| A-S5 | Fraud / bad debt | Превышение кредитного порога или material fraud case | Отключить автоодобрение для сегмента, перевести в manual review |
| A-S6 | Критичный инцидент, связанный с каналом или protected-сокращением | ≥1 | Стоп, RCA, rollback |
| A-S7 | Backlog юристов / кредитного комитета | Растёт более 2 недель | Эскалация в приоритетный комитет; временное ограничение экспресс-потока |
| A-S8 | Модель ПР4 даёт forecast, а факт выходит за интервал ±5% по ключевым метрикам | Ежемесячно | Перекалибровка модели; запрет на масштабирование до объяснения расхождения |
| A-S9 | Fallback readiness <80% при отказе от buy | К 31.12.2026 | Не масштабировать канал через внешний MVP без готового exit-плана и security review |
| A-S10 | Age of unresolved critical decisions >10 дней | Еженедельно | Эскалация на Правление; пилот не расширяется |

---

### 5.1.7. Что именно подтвердит улучшение U1 + U2

Пилот подтвердит U1 + U2, если одновременно выполнены условия:

```text
Главная метрика: инкрементальная маржа ≥100 млн ₽ на 100 заявок annualized
+ DSO delta ≤+10 дней
+ доля исключений ≤50% после 90 дней, целевое ≤35%
+ маржа ≥8%
+ 0 критичных инцидентов
+ fallback readiness ≥80%, если buy не подтверждён
+ контрольная группа показывает худший или статистически значимо более слабый результат
```

Если медианный срок ≤5 дней, но DSO ухудшается на +14 дней, а маржа ниже 8%, улучшение **не подтверждается**. Быстрый канал в таком случае является не преимуществом, а переносом риска в дебиторку.

## 6.3. Итоговая позиция по уверенности

| Улучшение | Уверенность | Почему |
|---|---|---|
| U1 | Средняя-низкая | Модель сверена с историей, но нет реального пилота; поведение клиентов не подтверждено |
| U2 | Низкая | Кредитные эффекты зависят от фактического fraud / bad debt / DSO, которые не измерены |
| U3 | Средняя | Бюджетная арифметика понятна, но требует аудита портфеля, protected-реестра, freeze registry и unification mapping |
| U4 | Низкая | Enabling и risk control; зависит от технической готовности данных, speed metrics, RCA и security review |
| U5 | Очень низкая | Риск-контроль; вероятность инцидента, protected-экономия и decision age не измерены |

Это честно: самая красивая цифра U3 имеет среднюю уверенность, а самые важные guardrails U2 / U5 имеют низкую уверенность, потому что без них U1 и U3 могут быть разрушены.

# 8. Защита: выступление на 7–10 минут

Ниже — сценарий выступления перед комиссией в роли руководства компании. Времена ориентировочные.

---

## 8.1. Бизнес и его цифра — 30 секунд

> ПАО «НК «Роснефть» — вертикально интегрированная нефтяная компания. Базовая выручка 2025 года — 8 236 млрд ₽. ИТ-бюджет оцениваем в 66–82 млрд ₽, рабочая база — 75 млрд ₽.  
>   
> Главная управленческая проблема после лебедей №3 и №4 и сценарных долгов С33 / С51 / С95 не в отсутствии технологий, а в конфликте требований: быстро захватить новых B2B-клиентов, не ухудшить дебиторку, сократить ИТ-бюджет на 25%, не сломать protected-сервисы КИИ, АСУ ТП, кассы АЗС, разблокировать телеметрию ЕЦПК, сверить бюджет унификации с секвестром, закрыть RCA после остановки и подписать критичные приоритеты.

## 8.2. Диагноз ИТ-функции с признаком — 1 минута

> ИТ-функция формально находится в состоянии «партнёр»: есть владельцы сервисов, каталог, SLA, связь с P&L, «Сибинтек», ЕЦПК, ERP, ИБ.  
>   
> Но после лебедей и сценарных долгов эта оценка проходит стресс-тест. Признаки деградации:  
> 1. нет подписанного приоритета между цифровым каналом и стандартизацией ЕЦПК;  
> 2. поддержка канала 0,5–1,0 млрд ₽/год не была заложена в waterfall;  
> 3. protected-сервисы требуют 10% экономии без formal risk acceptance;  
> 4. параллельная эксплуатация 30–90 дней тотально блокирует read-only телеметрию;  
> 5. после пропорционального сокращения людей не прибавилось, а нагрузка по каналу, скорингу, антифроду и исключениям растёт;  
> 6. метрики скорости добычи и переработки не согласованы, бюджет унификации 2–4 млрд ₽ не сверен с секвестром;  
> 7. нет freeze registry с BIS, fallback readiness, закрытого RCA и production change standard.  
>   
> Поэтому диагноз: партнёр в управляемом кризисе приоритетов. Нужен не «план улучшений всего», а проверяемый trade-off.

---

## 8.3. Пять улучшений с эффектом и уверенностью — 3 минуты

> Мы собрали пять улучшений.  
>   
> **Первое — U1: двухконтурный экспресс-онбординг B2B с fallback-gate.** Не 5 дней для всех, а только для низкорисковых типовых клиентов. Сложные клиенты уходят в исключительный контур с SLA 10–20 дней. Эффект: около 10,5 млрд ₽ годовой выручки пилотной когорты, это 0,13% выручки. Уверенность средне-низкая: модель сверена с историей, но поведение клиентов не проверено на пилоте. Важное дополнение по Сценарию 51 и 95: канал не должен зависеть от непроверенной M&A. Поэтому в U1 встроен fallback readiness gate: если buy не проходит DD, используется внешний подрядчик или внутренний MVP.  
>   
> **Второе — U2: кредитные guardrails.** Лимиты, предоплата, обеспечение, антифрод, когортный мониторинг DSO. Эффект консервативно 0,15 млрд ₽ как избежанный кредитный / операционный убыток. Это маленькая цифра, но критичная: без U2 U1 может ухудшить DSO на 14 дней и превратиться в канал просрочки. Уверенность низкая, нужны фактические данные по bad debt и fraud.  
>   
> **Третье — U3: управляемый секвестр ИТ-бюджета на 25%.** Чистая экономия около 18,8 млрд ₽. Это 25% ИТ-статьи, выше отраслевого коридора для одного улучшения по затратам. Объяснение: это не микроулучшение, а портфельная программа: заморозка некритичных проектов, аудит лицензий, инсорсинг, консолидация инфраструктуры, protected-фильтр. Дополнительно по Сценарию 51 и 33: нужен freeze registry с business impact statement, owner и review date, а бюджет унификации 2–4 млрд ₽ должен быть сверен с waterfall. Если gap >0, нужна дополнительная заморозка или formal Board risk acceptance. Уверенность средняя, но нижний сценарий 13,5 млрд ₽ не выполняет директиву, поэтому нужен quarterly trigger.  
>   
> **Четвёртое — U4: risk-based production/data change standard.** Нельзя одним правилом parallel run 30–90 дней замораживать и критичные производственные изменения, и некритичную передачу данных в ЕЦПК. Эффект ориентировочно 0,4 млрд ₽ как избежанные задержки и переделки. Но это не только телеметрия. По Сценарию 33 и «Остановке без правил» U4 включает согласование метрик скорости добычи и переработки, data readiness, RCA closure, change board, rollback и подпись владельца производства. Уверенность низкая: это enabling и risk control, а не прямой денежный результат.  
>   
> **Пятое — U5: protected risk acceptance и governance trust.** 100% сокращений protected-сервисов только через формальное принятие риска CISO, CFO и собственника. Net expected эффект около 0,05 млрд ₽: мы теряем потенциальную protected-экономию 0,45 млрд ₽, но избегаем ожидаемого инцидента примерно 0,50 млрд ₽. Дополнительно по «Потолку доверия»: критичные решения должны иметь owner и не висеть больше 10 рабочих дней. Уверенность очень низкая, зато это страховка от того, чтобы U3 не была выполнена ценой остановки, штрафа или сбоя касс АЗС.

## 8.4. Совокупный эффект против коридора и что ухудшается — 2 минуты

> Если просто сложить пять улучшений, получится 29,9 млрд ₽, или 0,36% выручки. Но это неправильная цифра.  
>   
> Мы вычитаем пересечения: U1 и U2 считают часть одного и того же кредитного риска; U3 и U5 пересекаются по protected-резерву; U4 частично уже учтён в ramp-up и оргрезерве. Минус 0,45 млрд ₽.  
>   
> Добавляем взаимное усиление: U3 финансирует поддержку канала для U1; U4 подписывает приоритеты и разблокирует данные; U2 делает U1 масштабируемым. Плюс 0,35 млрд ₽.  
>   
> Затем вычитаем execution bottleneck: кредитный блок, юристы, «Сибинтек», ЕЦПК, CDO, CFO. Людей после сокращения не прибавилось. Минус 1,8 млрд ₽.  
>   
> И отдельно вычитаем scenario constraints: бюджет унификации может быть не полностью сверен, заморозка может быть формальной, RCA может быть open, критичное решение может зависнуть. Минус 0,4 млрд ₽.  
>   
> Итог: совокупный выручка-эквивалент около 27,6 млрд ₽, или 0,34% выручки. Это внутри отраслевого коридора для набора пяти улучшений 0,2–1%. Чистый EBITDA-эффект — около 18,6 млрд ₽, или 0,23% выручки.  
>   
> Что ухудшается: часть сложных клиентов не получит 5 дней; вырастет очередь исключений; protected-экономия будет частично принесена в жертву безопасности; стандартизация ЕЦПК замедлится; понадобится приоритетный комитет и additional freeze при недоборе экономии; метрики скорости и RCA closure добавят governance-нагрузку. Мы не продаём картину «всё положительно».

## 8.5. План пилота и бюджет — 2 минуты

> Главный пользовательский пилот — U1 + U2 на реальных новых B2B-клиентах. Сегмент: мелкие и средние оптовики в 2–3 регионах, стандартный продукт, годовой потенциал 150–250 млн ₽, без экспорта и спецлогистики. Это не самый удобный сегмент, но он приносит деньги и находится в окне захвата.  
>   
> Контрольная группа: сопоставимые заявки в контрольных регионах по старому процессу, cluster randomization, предпериод 3 месяца, shadow-скоринг.  
>   
> Главная метрика: инкрементальная маржа на 100 заявок в annualized выражении. Порог — 100 млн ₽. Модель даёт около 118 млн ₽, но порог ниже, чтобы не натягивать результат.  
>   
> Защитные метрики: DSO не хуже baseline более чем на 10 дней, доля исключений не выше 50% после 90 дней, маржа не ниже 8%, 0 критичных инцидентов, backlog юристов и кредитного комитета не растёт более 2 недель, fallback readiness не ниже 80%, age of unresolved critical decisions не выше 10 дней.  
>   
> Критерии остановки: если DSO ухудшается >10 дней два месяца подряд, если исключения >50%, если главная метрика к 120-му дню ниже 60 млн ₽ на 100 заявок, если fraud или инцидент — пилот останавливается, а не дожимается.  
>   
> Параллельно делаем управленческие пилоты по сценариям: speed metrics и data readiness по 3 направлениям; unification reconciliation gap; freeze registry и BIS; fallback readiness и DD gate; production change standard и RCA closure; governance trust через age of unresolved decisions.  
>   
> Бюджет: разово база 4,0 млрд ₽, ежегодно около 1,27 млрд ₽ без protected-costs. Окупаемость в ожидаемом сценарии — около 2,6 месяца, в пессимистичном — 7,5 месяца, с опциональными fallback / DD затратами — до 8,6–10,2 месяца. Но окупаемость не главное: главное — не выполнить секвестр ценой protected-инцидента и не ускорить канал ценой просрочки.

## Вопрос 1. Откуда взята любая названная цифра?

### U1: 10,5 млрд ₽ выручки пилота

Ответ:

> Это не факт, а модельный output ПР4. База: выручка 2025 г. 8 236 млрд ₽; высвобождаемый спрос как прокси 5–10% — 412–824 млрд ₽; адресуемый пилотный сегмент 10–15%; перехват 10–20%; доля регулярных отгрузок 70–80%; средний годовой объём нового клиента 150–250 млн ₽. Консервативный диапазон 3 / 9–12 / 18 млрд ₽. Для пяти улучшений взято среднее 10,5. Уверенность средне-низкая, потому что нет реального пилота.

### U2: 0,15 млрд ₽

Ответ:

> Это консервативная оценка избежанного кредитного / операционного убытка. Лебедь №3 даёт риск DSO +14 дней; ПР3 оценивал устойчивое ухудшение 0,15–0,45 млрд ₽/год. Мы взяли нижнюю консервативную величину 0,15 как net effect после пересечения с U1. Цифра не высокая, потому что не хотим выдавать guardrail за большое денежное улучшение.

### U3: 18,8 млрд ₽

Ответ:

> Waterfall: валовая экономия 22–30 млрд ₽; минус protected-расходы 3,5–7,5; минус поддержка канала 0,5–1,0; минус оргрезерв 0,6–1,4. База чистой экономии 18,8. Это согласовано с ПР2 / ПР3 / ПР4. Уверенность средняя, но нижний сценарий 13,5 млрд ₽ не выполняет директиву 18,75, поэтому нужен триггер дополнительной заморозки. Дополнительно: freeze registry и unification reconciliation должны подтверждать, что экономия не формальная.

### U4: 0,40 млрд ₽

Ответ:

> Оценка избежанных задержек и переделок при переходе от тотального parallel run 30–90 дней к risk-based режиму для read-only телеметрии, плюс enabling-эффект от согласования speed metrics, data readiness и production change standard. Это не эффект ИИ Г5. Это enabling и risk-control цифра. Уверенность низкая, требуется аудит интерфейсов, data contract, RCA closure и security review.

### U5: 0,05 млрд ₽ net

Ответ:

> Прямая потеря: 10% потенциальной экономии по protected-статьям 3,5–7,5 млрд ₽, база 0,45. Ожидаемый избежанный инцидент: стоимость критичного инцидента 0,5–2,8 млрд ₽, консервативная вероятностная оценка 0,50. Net +0,05. Governance trust может снизить задержки, но добавляет нагрузку. Уверенность очень низкая, потому что вероятность инцидента и decision age не измерены. Но без этого U3 может быть выполнена формально и опасно.

## Вопрос 3. Что произойдёт, если бюджет урежут наполовину?

Ответ:

> Базовый разовый бюджет 4,0 млрд ₽. Половина — 2,0 млрд ₽.  
>   
> В этом случае мы не можем финансировать полный канал, полную стандартизацию и все сценарные аудиты одновременно. Приоритет был бы такой:
> 1. 0,4–0,6 млрд ₽ — аудит портфеля, protected-реестр, waterfall, freeze registry, приоритетный комитет;
> 2. 0,8–1,0 млрд ₽ — fallback MVP цифрового канала, не полная интеграция;
> 3. 0,2–0,3 млрд ₽ — минимальный data contract и production change standard для 1–2 критичных контуров;
> 4. полное масштабирование U1, расширение ЕЦПК и будущая Г5 откладываются.  
>   
> Совокупный эффект снизится. Ориентировочно чистый EBITDA-эффект может упасть до 10–14 млрд ₽, окупаемость — до 4–6 месяцев. Главное: при урезанном бюджете нельзя резать protected-сервисы, чтобы «добрать» цифру, и нельзя запускать канал без fallback readiness. Это прямой путь к инциденту или срыву окна.

## Вопрос 7. Как сверстан бюджет унификации 2–4 млрд ₽ с секвестром?

Ответ:

> Через U3 и метрику M15 `unification_reconciliation_gap`.  
>   
> Формула:

```text
unification_reconciliation_gap =
approved_unification_budget
− earmarked_protected_or_freeze_source
```

> Целевое значение: ≤0. Если gap >0, есть три легальных варианта:
> 1. бюджет унификации уже внутри protected costs — нужно показать mapping;
> 2. запускается дополнительная заморозка некритичных проектов на 2,0–6,5 млрд ₽;
> 3. Правление подписывает formal risk acceptance.  
>   
> Нельзя одновременно считать protected costs 3,5–7,5 млрд ₽, отдельно вычитать унификацию 2–4 млрд ₽ и заявлять, что это разные расходы, если они не разведены в реестре. Это стоп-критерий S13.

## Вопрос 10. Как закрыт RCA после остановки установки НПЗ?

Ответ:

> Это часть U4 и sub-процесса ПР3 2E: production change standard.  
>   
> Метрика M18: RCA closure rate и production change compliance. Целевое 100%. Любое изменение АСУ ТП, MES, SCADA, historian, телеметрии КИИ требует:
> - RCA по предыдущим критичным инцидентам;
> - change board;
> - parallel run;
> - rollback plan;
> - подпись владельца производства;
> - CISO approval для ИБ / КИИ;
> - data contract для read-only телеметрии.  
>   
> Если RCA open >30 дней, срабатывает стоп-критерий S17: production changes останавливаются. Если изменение сделано без change control, S18: rollback, RCA, стоп контура.

## Вопрос 11. Почему руководители направлений должны доверять корпоративному ИТ?

Ответ:

> Потому что ПР5 не предлагает им «стандартизацию сверху». Она включает:
> 1. согласование метрик скорости добычи и переработки с владельцами направлений;
> 2. baseline или честный статус «не измерено» с планом замера;
> 3. read-only телеметрию без изменения производственных уставок;
> 4. production change standard и rollback;
> 5. unification budget reconciliation, чтобы унификация не ломала секвестр;
> 6. приоритетный комитет с owner и age of unresolved decisions.  
>   
> Это снимает «Потолок доверия»: решения становятся подписанными, метрики — согласованными, изменения — контролируемыми.

# 13. Итоговая формулировка для комиссии

> Пять улучшений для ПАО «НК «Роснефть» — это не план «ускорить цифровой канал и сократить ИТ». Это управляемый trade-off после лебедей №3 и №4 и сценарных долгов С33 / С51 / С95 / «Остановка без правил» / «Потолок доверия».  
>   
> Мы проверяем быстрый B2B-онбординг только для низкорисковых клиентов и одновременно ставим кредитные guardrails, чтобы скорость не превратилась в просрочку. Мы выполняем секвестр ИТ-бюджета, но не режем protected-сервисы без formal risk acceptance, явно закладываем поддержку канала, вводим freeze registry с BIS и сверяем бюджет унификации 2–4 млрд ₽ с секвестром. Мы разблокируем read-only телеметрию через risk-based parallel run, согласовываем метрики скорости добычи и переработки, закрываем RCA и вводим production change standard, чтобы не заморозить ЕЦПК общим правилом для производственных изменений. Мы управляем опцией buy / build / partner через DD, retention, integration cost и fallback readiness, потому что белый лебедь №7 не назначен.  
>   
> Совокупный эффект — не сумма пяти чисел. После пересечений, взаимного усиления, execution bottleneck и scenario constraints он составляет около **27,6 млрд ₽ выручка-эквивалента**, или **0,34% выручки**, и около **18,6 млрд ₽ чистого EBITDA-эффекта**, или **0,23% выручки**. Это внутри отраслевого коридора для набора улучшений.  
>   
> Главное решение руководства — не «давать деньги на всё», а утвердить пользовательский пилот с контрольной группой, сценарные аудиты, стоп-триггеры и protected-фильтр. Если пилот не подтверждает маржу и DSO, масштабирование останавливается. Если секвестр угрожает КИИ, АСУ ТП, кассам АЗС, поддержке канала или бюджету унификации, сокращение возвращается на formal risk acceptance. Если метрики скорости, RCA или критичные решения не согласованы, унификация и будущая Г5 не запускаются.
