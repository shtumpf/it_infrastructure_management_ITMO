# 1. Что изменилось в ПР3 по сравнению с версией 2.0 из-за лебедей №3 и №4

## 1.1. Лебедь №3: быстрый онбординг B2B против кредитного риска

### Прямые последствия события

- в первую когорту цифрового канала приходит много мелких оптовиков с короткой историей и слабой отчётностью;
- автоматическое одобрение лимита для стандартных клиентов пропускает слабых контрагентов быстрее, чем кредитный комитет успевает оценить риск;
- через квартал DSO по новой когорте ухудшается на **14 дней**;
- коммерческий блок требует держать окно захвата в **5 рабочих дней**;
- казначейство и кредитный блок требуют ужесточить скоринг;
- доля сложных клиентов в очереди исключений растёт до **50%**;
- юристы и кредитный комитет перегружены;
- людей у ИТ после пропорционального сокращения не прибавилось.

### Что это меняет в ПР3

Процесс онбординга нового B2B-клиента больше не может проектироваться как единый быстрый поток «заявка → автоодобрение → отгрузка».

Нужны:

1. **два контура**:
   - экспресс-контур для низкорисковых типовых клиентов;
   - исключительный контур для сложных, непонятных, крупнолимитных, экспортных и слабо отчётных контрагентов;
2. **кредитные guardrails**:
   - лимит нового клиента;
   - предоплата / частичная предоплата;
   - обеспечение / банкгарантия / страхование;
   - ограничение первой отгрузки;
   - антифрод и KYC;
   - мониторинг DSO по когорте;
3. **стоп-триггер**:
   - если DSO новой когорты ухудшается более чем на 10 дней, экспресс-режим для сомнительного сегмента приостанавливается;
4. **приёмка результата агента**:
   - агент может читать документы, извлекать реквизиты, проверять полноту пакета, обогащать данными и предлагать скоринг, но не принимает финальное кредитное решение выше порога.

---

## 1.2. Лебедь №4: секвестр protected-сервисов и блокировка архитектуры

### Прямые последствия события

- собственник принимает реестр protected-сервисов, но требует, чтобы даже protected-статьи дали по **10% экономии**;
- в protected-список попадают:
  - SOC и мониторинг КИИ;
  - АСУ ТП;
  - кассы АЗС;
  - цифровой канал;
- CISO заявляет, что ниже текущего уровня мониторинг объектов КИИ опускать нельзя;
- коммерческий директор обнаруживает, что поддержка цифрового канала в объёме **0,5–1,0 млрд ₽/год** не заложена в waterfall;
- правило параллельной эксплуатации **30–90 дней** блокирует не только перенос интерфейсов MES, но и передачу телеметрии в ЕЦПК;
- без телеметрии не работает единый слой данных;
- «Сибинтек» должен выбрать, кого из команд ЕЦПК оставить на канал, а кого направить на стандартизацию, но решение никто не готов подписать.

### Что это меняет в ПР3

Процесс управления ИТ-портфелем и секвестром должен быть перестроен так, чтобы:

1. protected-сервисы не резались базово;
2. требование 10% экономии по protected-статьям исполнялось только через **formal risk acceptance** CISO / CFO / собственника;
3. поддержка цифрового канала **0,5–1,0 млрд ₽/год** стала явной строкой waterfall;
4. parallel run стал **risk-based**:
   - строгий 30–90 дней для производственного управления, АСУ ТП, критичных MES-интерфейсов;
   - ускоренный режим для read-only телеметрии в ЕЦПК при наличии data contract и security review;
5. появился владелец решения по приоритету «канал vs стандартизация ЕЦПК»;
6. Г5 «ИИ / оптимизация переработки» осталась в резерве как ограничитель, а не как процесс ПР3.

---

## 1.3. Белый лебедь №7 не назначен

Абзац про покупку небольшой технологической компании не является обязательным игровым событием. Поэтому:

- Г4 остаётся **условной опцией**;
- в процессах ПР3 присутствует gate **build / buy / partner**;
- если due diligence не пройден, используется fallback: внешний подрядчик или внутренняя MVP-команда;
- M&A не включается в гарантированный эффект.

## 2.3. Почему Г5 не взята как отдельный процесс ПР3

Г5 может дать эффект, но:

- телеметрия в ЕЦПК блокируется parallel run 30–90 дней;
- нет подтверждённого RCA по остановке установки НПЗ;
- нет change control для производственных контуров;
- data readiness пилотных НПЗ не измерена;
- лебедь №4 усилил риск того, что任何 изменение MES / АСУ ТП без controlled parallel run может привести к остановке.

Поэтому Г5 учитывается в ПР3 только как ограничитель:

> Любые процессы, затрагивающие производственный контур, АСУ ТП, MES, SCADA, historian и телеметрию КИИ, не могут быть изменены без parallel run, rollback-плана, data contract и подписи владельца производства.

# 3. Процесс 1. Онбординг нового B2B-клиента

## 3.1. Границы процесса

**Вход:** заявка нового B2B-клиента на поставку нефтепродуктов / продуктов переработки / типового оптового продукта.

**Выход:**

- для экспресс-контура: клиент подключён, лимит / предоплата / обеспечение установлены, первая отгрузка разрешена, инвойс сформирован, когорта поставлена под мониторинг DSO;
- для исключительного контура: клиент либо подключён по ручному / гибриdnому SLA, либо отказ с фиксацией причины.

**В процессе участвуют:**

- новый B2B-клиент;
- коммерческий блок / менеджер;
- product owner цифрового канала;
- KYC / комплаенс;
- кредитный аналитик;
- кредитный комитет;
- юристы;
- логистика;
- производство / отгрузка;
- SAP / 1С / ERP;
- scoring engine / антифрод;
- BI / когортный мониторинг;
- агент ИИ / automation layer;
- «Сибинтек» / fallback-подрядчик;
- CISO / ИБ для контроля данных и доступа.

**Не входит в процесс:**

- изменение АСУ ТП, MES, SCADA, производственных уставок;
- финальное кредитное решение выше порога без человека;
- сокращение мониторинга КИИ;
- обход SAP / 1С / ЕЦПК;
- самостоятельная подпись договоров агентом.

---

## 3.2. Схема AS-IS в текстовом виде

```text
Клиент / менеджер
  → регистрация заявки
  → сбор документов
  → KYC / комплаенс
  → первичный скоринг / антифрод
  → кредитный лимит
      ├─ стандартный клиент → договор
      └─ сложный клиент → очередь исключений → кредитный комитет / юристы
  → логистика и первая отгрузка
  → заведение в SAP / 1С
  → инвойс / ЭДО
  → оплата
  → мониторинг дебиторки
```

После лебедя №3 опасный сценарий AS-IS / ранний цифровой поток:

```text
Заявка → автоматическое одобрение стандартного лимита → быстрая отгрузка
  → рост DSO по новой когорте на +14 дней
  → рост сложных исключений до 50%
  → перегрузка юристов и кредитного комитета
  → конфликт метрик: выручка растёт, просрочка тоже растёт
```

## 3.5. Процесс TO-BE: двухконтурный онбординг

### Контур A. Экспресс-онбординг для низкорисковых типовых клиентов

Критерии попадания в экспресс-контур:

- стандартный продукт;
- небольшой первый объём;
- приемлемый скоринг;
- нет признаков мошенничества;
- клиент согласен на предоплату / частичную предоплату или обеспечение;
- кредитный лимит не превышает установленный порог;
- нет экспортной /Special contract сложности;
- нет requerment на индивидуальную логистику сверх типовых маршрутов.

Целевой срок:

> Медианное время экспресс-онбординга — **не более 5 рабочих дней**.

### Контур B. Исключительный онбординг для сложных клиентов

Критерии попадания в исключительный контур:

- крупный запрашиваемый лимит;
- слабая отчётность;
- короткая история платежей;
- нестандартный продукт / экспорт;
- сложная логистика;
- признаки мошенничества или KYC-риска;
- необходимость индивидуального договора;
- клиент не принимает предоплату / обеспечение.

Целевой срок:

> Не обещать 5 дней. Установить честный SLA: **10–20 рабочих дней** в зависимости от типа сложности.

## 3.8. DORA для Процесса 1

DORA применяются к цифровому каналу и non-production контуру онбординга. Производственные АСУ ТП / MES в DORA-контур П1 не входят.

| DORA-метрика | Базовое значение до | Целевое значение после | Источник / статус | Комментарий |

## 3.9. Место агента в Процессе 1

### Вопрос 1. Где агент включается в процесс?

Агент включается на шагах:

- сбор и проверка документов;
- извлечение реквизитов;
- проверка полноты пакета;
- обогащение данными о контрагенте;
- первичный risk-score;
- маршрутизация в экспресс или исключение;
- подготовка шаблонного договора;
- контроль дедлайнов exception queue;
- формирование отчёта по DSO новой когорты.

# 4. Процесс 2. Управление ИТ-портфелем, секвестром, protected-сервисами, поддержкой канала и телеметрией ЕЦПК

## 4.1. Границы процесса

**Вход:** директива собственника сократить ИТ-бюджет на 25%, требование protected-сервисов, потребность в цифровом канале, блокировка телеметрии ЕЦПК, конфликт ресурсов «Сибинтек» / ЕЦПК.

**Выход:**

- утверждённый waterfall чистой экономии;
- реестр protected-сервисов;
- реестр замороженных / сокращаемых проектов;
- явная строка поддержки цифрового канала 0,5–1,0 млрд ₽/год;
- formal risk acceptance, если собственник настаивает на 10% экономии по protected-статьям;
- risk-based parallel run и data contract для read-only телеметрии;
- подписанный приоритет: канал vs стандартизация ЕЦПК.

**В процессе участвуют:**

- CFO;
- CDO;
- CISO;
- коммерческий директор;
- руководитель кредитного блока / казначейство;
- PMO;
- procurement;
- юристы;
- «Сибинтек»;
- ЕЦПК;
- производственные дирекции добычи и переработки;
- владельцы SAP / 1С / касс АЗС / SOC / КИИ;
- инвесткомитет / Правление при эскалации.

## 4.2. Схема AS-IS в текстовом виде

```text
Директива −25%
  → сбор ИТ-бюджета и портфеля
  → попытка пропорционального сокращения
  → protected-сервисы попадают под резку
  → отсутствие строки поддержки канала в waterfall
  → долгий аудит лицензий и проектов
  → согласование с бизнесом
  → решение комитета
  → изменение контрактов
  → parallel run 30–90 дней применяется тотально
  → телеметрия в ЕЦПК блокируется
  → «Сибинтек» не понимает приоритет: канал или стандартизация
```

## 4.5. Процесс TO-BE: управляемый секвестр с protected-фильтром и разблокировкой read-only телеметрии

### Ключевые принципы TO-BE

1. **Protected-сервисы не режутся базово.**  
   SOC, мониторинг КИИ, АСУ ТП, кассы АЗС, критичные финансовые закрытия и цифровой канал не подлежат пропорциональному сокращению.

2. **10% экономия по protected-статьям возможна только через formal risk acceptance.**  
   Если собственник настаивает, CFO, CISO и Правление подписывают:
   - какой сервис сокращается;
   - на сколько;
   - какой риск принимается;
   - кто владелец риска;
   - какой rollback / compensating control.

3. **Поддержка цифрового канала 0,5–1,0 млрд ₽/год — обязательная строка waterfall.**  
   Её нельзя прятать в «новые расходы» или забывать при расчёте чистой экономии.

4. **Parallel run должен быть risk-based.**
   - 30–90 дней для производственного управления, АСУ ТП, критичных MES-интерфейсов;
   - ускоренный режим для read-only телеметрии в ЕЦПК при data contract, isolation, security review и rollback.

5. **Приоритет «канал vs стандартизация ЕЦПК» должен быть подписан.**  
   Владелец — CDO. При отсутствии консенсуса за 5 рабочих дней — эскалация на Правление / уполномоченный комитет.

## 4.8. DORA для Процесса 2

DORA в классическом виде применимы к software delivery. Процесс 2 — это портфельное / финансовое / risk-управление, поэтому прямые DORA-метрики не являются основными.

| Вариант | Решение |
|---|---|
| Применять DORA к Процессу 2 | Не применяется как основной набор метрик |
| Почему пропущено | Процесс не является pipeline выкатки кода; его узкие места — решения, бюджеты, контракты, risk acceptance и change control |
| Чем заменено | Decision cycle time, budget forecast accuracy, protected risk acceptance rate, telemetry SLA, change failure rate для производственных / data-изменений |

### Альтернативные операционные метрики для Процесса 2

| Метрика | Базовое значение | Целевое значение | Источник / способ съёма |
|---|---:|---:|---|
| Decision cycle time по критичным приоритетам | 15–30 дней | ≤5 рабочих дней, эскалация при нарушении | Decision log, протоколы |
| Budget forecast accuracy по чистой экономии | не измерено | отклонение ≤10% поквартально | CFO / PMO monthly forecast |
| Protected risk acceptance rate | 0% формально подписанных risk acceptance | 100% сокращений protected-сервисов имеют протокол risk acceptance | CISO / CFO / Правление |
| Telemetry SLA для read-only ЕЦПК | не измерено / заблокировано | доступность ≥99%, latency по data contract | API monitoring, data architect |
| Change failure rate для production / data изменений | не измерено | ≤5–10% для controlled changes; 0 критичных инцидентов | Change records + incident log |

# 5. Эффект и trade-off

## 5.1. Мост от скорости к деньгам для Процесса 1

Исходная точка:

- медианный срок онбординга стандартного B2B-клиента AS-IS — **28–35 рабочих дней**, база **32,5 рабочих дней**;
- целевой срок экспресс-контура TO-BE — **≤5 рабочих дней**.

Разница:

```text
32,5 − 5 = 27,5 рабочих дня ≈ 5,5 недель
```

Если недельная вероятность потери лида составляет 2–5%, то выигрыш по выживаемости лида:

| Недельная вероятность потери лида | Выживаемость AS-IS за 6,5 недель | Выживаемость TO-BE за 1 неделю | Прирост выживаемости |
|---:|---:|---:|---:|
| 2% | ≈87,7% | 98,0% | ≈10,3 п.п. |
| 3% | ≈82,0% | 97,0% | ≈15,0 п.п. |
| 5% | ≈71,7% | 95,0% | ≈23,3 п.п. |

Консервативно для эффекта берётся прирост **8–18 п.п.**, а не максимальные 23 п.п., потому что часть клиентов уходит не из-за срока, а из-за цены, наличия продукта, логистики и доверия к бренду.

## 5.5. Совокупный эффект: не простая сумма

### Валовый эффект активного портфеля

| Компонент | Минимум | База | Максимум |
|---|---:|---:|---:|
| Выручка П1 / Г1 | 3,0 млрд ₽ | 9–12 млрд ₽ | 18,0 млрд ₽ |
| Чистая экономия П2 / Г2 | 13,5 млрд ₽ | 18,8 млрд ₽ | 22,0 млрд ₽ |
| Итого валовый эффект | **16,5 млрд ₽** | **27,8–30,8 млрд ₽** | **40,0 млрд ₽** |
| Как доля выручки 2025 г. | **0,20%** | **0,34–0,37%** | **0,49%** |

Статус по отраслевому коридору для набора улучшений:

- коридор: 0,2–1% выручки;
- базовый эффект ПР3: 0,34–0,37%;
- верхний: 0,49%;
- нижний: 0,20%, ровно нижняя граница.

Вывод:

> Совокупный валовый эффект находится в коридоре набора улучшений. Пессимистичный сценарий находится на нижней границе и требует стоп-решения по масштабированию Г1.

### Чистый вклад после trade-off

| Статья | Минимум | База | Максимум |
|---|---:|---:|---:|
| Маржинальный вклад П1 | 0,24 млрд ₽ | 0,72–0,96 млрд ₽ | 2,16 млрд ₽ |
| Чистая экономия П2 | 13,5 млрд ₽ | 18,8 млрд ₽ | 22,0 млрд ₽ |
| − Цена приёмки агента П1 | −0,003 млрд ₽ | −0,003 млрд ₽ | −0,002 млрд ₽ |
| − Цена приёмки агента П2 | −0,001 млрд ₽ | −0,001 млрд ₽ | −0,0007 млрд ₽ |
| − Устойчивое ухудшение П1 | −0,45 млрд ₽ | −0,30 млрд ₽ | −0,15 млрд ₽ |
| − Opportunity cost замороженных проектов П2 | −3,0 млрд ₽ | −2,0 млрд ₽ | −1,5 млрд ₽ |

Важно:

- чистый вклад ниже валового эффекта, потому что учитывает ухудшения;

- для коридора сравнивается валовый эффект улучшений, а чистый вклад показывает управленческую цену.

## 5.6. Trade-off: что ухудшается и во что это обходится

| Мера | Что улучшаем | Что ухудшаем | Цена / риск |
|---|---|---|---|
| Экспресс-онбординг только для низкорисковых | Скорость захвата, конверсия, окно 6 месяцев | Часть сложных клиентов не проходит за 5 дней | Потеря части сделок или необходимость ручной очереди |
| Ужесточение скоринга и guardrails | Снижение DSO и bad debt | Более длинный онбординг для пограничных клиентов | Упущенные клиенты, нагрузка на кредитный блок |

## 5.7. Критерии остановки и гейты

### Для Г1 / Процесса 1

| Триггер | Действие |
|---|---|
| DSO новой когорты ухудшается >10 дней | Приостановить экспресс-режим для сегмента |
| Доля исключений >50% после 90 дней | Пересмотреть критерии экспресс-контура, усилить предоплату / обеспечение |
| Годовая выручка пилота <4 млрд ₽ на горизонте 6–9 мес. | Не масштабировать; Г1 не подтверждается как эффект канала |
| Маржа <8% | Пересмотреть скидки, логистику, продуктовый микс |
| Контрольная группа старого процесса показывает сопоставимый результат | Остановить утверждение, что эффект даёт цифровой канал |
| Fraud / bad debt выше порога | Отключить автоодобрение для сегмента |

### Для Г2 / Процесса 2

| Триггер | Действие |
|---|---|
| Квартальная чистая экономия annualized <18,75 млрд ₽ | Запустить дополнительную заморозку некритичных проектов на 2,0–6,5 млрд ₽ |
| Критичный инцидент из-за секвестра | Остановить сокращение соответствующего контура, rollback, RCA |
| Protected-сервис сокращён без risk acceptance | Немедленный возврат бюджета или formal risk acceptance с последствиями |
| Поддержка канала не заложена в waterfall | Пересчитать чистую экономию, не объявлять директиву выполненной |
| Замороженные проекты размораживаются без NPV-пересмотра | Г2 не подтверждается |

### Для Г3 / governance

| Триггер | Действие |
|---|---|
| Приоритет канал / ЕЦПК не подписан >5 рабочих дней | Эскалация на Правление / уполномоченный комитет |
| Committee cycle time >10 рабочих дней | Пересоставить комитет, сократить повестку, ввести delegated authority |
| Решение без владельца риска | Не принимать; вернуть на доработку |

### Для Г5 / производственный контур

| Триггер | Действие |
|---|---|
| Нет RCA по остановке НПЗ | Не запускать производственные изменения |
| Нет change control / parallel run | Не трогать АСУ ТП / MES |
| Нет read-only telemetry SLA и data contract | Г5 остаётся в резерве |
| Изменение вызвало инцидент | Rollback, стоп, RCA |

# 9. Итоговая формулировка ПР3 после лебедей №3 и №4

ПР3 версии 3.0 не пытается «ускорить всё и сократить всё». Она проектирует два управляемых процесса в условиях двойного зажима.

## По лебедю №3

Быстрый цифровой B2B-канал возможен только как **двухконтурный процесс**:

- экспресс-контур ≤5 рабочих дней только для низкорисковых типовых клиентов;
- исключительный контур 10–20 рабочих дней для сложных контрагентов;
- обязательные кредитные guardrails;
- когортный мониторинг DSO;
- стоп-триггер при ухудшении DSO более чем на 10 дней;
- агент помогает, но не принимает финальные кредитные решения.

## По лебедю №4

Секвестр ИТ-бюджета возможен только как **управляемая портфельная программа**:

- protected-сервисы не режутся базово;
- 10% экономия по protected-статьям только через formal risk acceptance;
- поддержка цифрового канала 0,5–1,0 млрд ₽/год явно заложена в waterfall;
- parallel run становится risk-based;
- read-only телеметрия в ЕЦПК может быть разблокирована через data contract и security review;
- приоритет «канал vs стандартизация» подписывается приоритетным комитетом с эскалацией на Правление.

## Главный результат

Валовый эффект активного портфеля ПР3:

```text
16,5–40,0 млрд ₽, или 0,20–0,49% выручки 2025 г.
```

Базовый валовый эффект:

```text
27,8–30,8 млрд ₽, или 0,34–0,37% выручки 2025 г.
```

Чистый вклад после устойчивых ухудшений и opportunity cost:

```text
10,3–21,8 млрд ₽, база ≈17,2–17,5 млрд ₽.
```

Это согласуется с отраслевым коридором для набора улучшений и одновременно показывает честную цену: скорость онбординга не бесплатна, секвестр не безрисков, а единый слой данных не строится без change control и подписанных приоритетов.
